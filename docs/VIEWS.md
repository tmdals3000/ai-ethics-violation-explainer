# 뷰 구성

화면(`app.py`, Streamlit)은 **공통 사이드바 + 탭 4개(P1~P4)** 로 되어 있습니다. 탭마다 PDF 의 분석 질문 하나에 답합니다.

```
┌─ 사이드바 (공통) ──────┐ ┌─ P1 규칙 찾기 │ P2 판정 비교 │ P3 오판 원인 │ P4 수정 효과 ──────┐
│ 공통 필터               │ │                                                                │
│  출처 · 규칙 · 응답 LLM │ │   탭마다: 지표 → 주 시각화 → 보조 표 → 선택한 텍스트 상세      │
│  판정 모델 · 사람 라벨   │ │                                                                │
│  판정 결과 · 임계값      │ │                                                                │
│ 선택한 텍스트 (연동)     │ │                                                                │
└────────────────────────┘ └────────────────────────────────────────────────────────────────┘
```

## 공통 (모든 탭)

| 요소 | 내용 | PDF 요구 |
|---|---|---|
| 공통 필터 | 출처, 규칙(대분류), 응답 LLM, 판정 모델, 사람 라벨(위반/정상), 판정 결과(오판 있음/모두 맞음), 임계값 직접 지정 | 출처·분할·규칙·판정 모델·판정 결과 필터 |
| 선택 연동 | 어느 탭에서든 텍스트를 클릭하면 `선택한 텍스트`가 바뀌고, 모든 탭에서 같은 텍스트가 강조됨 (트리·산점도·지도에서 검은 테두리) | 뷰 간 선택 연동 |
| 원문 보기 | 기본은 ID·라벨·정답 규칙만 보이고, "원문 보기"를 켜야 질문·응답이 보임 | 유해 문장 기본 가림 |
| 건수 표시 | 비율 옆에 항상 건수, 10건 미만 칸은 흐리게 | 건수가 적은 칸 흐리게 |

임계값: 기본은 기준 모델 0.5, 팀 판정기 DNA dev F1 최대(0.57). "직접 지정"을 켜면 모든 모델에 같은 값을 씀.

## P1 규칙 찾기 — "왜 이 규칙이 찾아졌고, 어디서 정답과 갈라졌나?"

| 구성 | 인코딩 | 상호작용 |
|---|---|---|
| 지표 4개 | top-1, top-3, 효율(비교 노드 비율), 텍스트 수 | τ 슬라이더를 움직이면 바로 다시 계산 |
| 규칙 트리 (트리맵) | 사각형 = 노드(대 → 중 → 소), 색 = 선택한 텍스트와의 유사도, ★ = 정답 경로, ✓ = BFS 로 남긴 중분류·상위 5개 후보 | 출처(DNA/Jigsaw) 전환, 노드에 마우스를 올리면 유사도 |
| 상위 5개 후보 표 | 후보 이름, 유사도, 정답 표시, '기본' 판정에서 최댓값을 낸 후보 ◀ | |
| 경계 사례 표 | τ±0.02 에서 1위 규칙이 바뀌는 텍스트 | 행 클릭 → 그 텍스트 선택 |
| 자주 틀리는 가지 | 정답 중분류별 top-1 (막대 색 = 정확도, 숫자 = 건수) | |

## P2 판정 비교 — "모델과 사람이 어디서 엇갈리고, 오판이 어디에 쏠리나?"

| 구성 | 인코딩 | 상호작용 |
|---|---|---|
| 지표 표 | 출처 × 판정 모델: ROC-AUC, PR-AUC, F1, κ(사람), 오판 비율, 임계값 | 필터 반영 |
| 오판 행렬 (히트맵) | 행 = 묶음, 열 = 판정 모델, 색 = 오판 비율, 글자 = 비율(오판/건수) | 묶음 기준 전환: 출처 · 규칙(대/중분류) · 응답 LLM |
| 두 모델 산점도 | x·y = 두 모델의 위반 확률, 색 = 사람 라벨, 모양 = 출처, 점선 = 임계값 | 축 모델 선택, 점 클릭 → 선택 |

## P3 오판 원인 — "잘못된 판정은 왜 생겼나?"

| 구성 | 인코딩 | 상호작용 |
|---|---|---|
| 모델 × 원인 표 | 잘못된 판정 (텍스트, 모델) 쌍의 원인별 건수 | 출처 전환, 기준 k 슬라이더 → 바로 다시 진단 |
| 텍스트 지도 | UMAP 좌표, 회색 = 맞힌 텍스트, 색 = 원인, ◆ = 정답 규칙이 상위 k 밖 | 지도에 표시할 모델 선택, 점 클릭 → 선택, 상자·올가미로 영역 선택 |
| 원인 분포 막대 | 선택 영역(없으면 전체)의 원인별 건수와 비율 | 영역 선택과 연동 |
| 진단 상세 | 선택한 텍스트의 모델별 위반 확률·임계값·판정·원인 | |

원인 규칙 (위에서부터 처음 해당하는 하나): 1 규칙 찾기 → 2 라벨 확인 필요 → 3 규칙 문장 → 4 판정 모델. 정의는 `diagnose.py`.

## P4 수정 효과 — "무엇을 고치면 얼마나 나아지나?"

| 구성 | 내용 |
|---|---|
| 정답 규칙 효과 | ShieldGemma 기본(후보 5개) → 규칙 문장만(정답 규칙)의 AUC 변화 |
| 처음 보는 규칙 실험 | 규칙(DNA 위해 유형 12개, Jigsaw 2개)별 AUC: 기본 · 규칙 제외 · 규칙 문장만, 하락폭과 회복폭 |
| 팀 프롬프트 수정 전후 | 원칙 문장 v1·v2·v3 와 기준 ShieldGemma 의 ROC-AUC·PR-AUC 막대 |
| 임계값 수정 | 원래 설정과 바꾼 설정의 지표를 나란히, 뒤집힌 판정(맞게/틀리게) 목록, 원래 값으로 되돌리기, 수정안 저장·CSV 받기 |
