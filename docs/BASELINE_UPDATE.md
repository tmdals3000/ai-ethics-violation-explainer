# Baseline v2 변경 기록 (2026-11-12)

Project 4 PDF 4–6쪽의 필수 상호작용과 8–9쪽의 팀 판정·규칙 개선 실험 요구를 기준으로 수정했다.
test는 평가하거나 규칙 수정에 사용하지 않았다. 기존 결과는 `data/baseline_before_20261112/`에 보관했다(커밋 제외).
현재 출력은 `runs/baseline_v2/`다. 기존 `results/`의 실행 계정 쓰기 권한이 제한되어 새 버전 폴더로 분리했다.
GPU 판정 완료 후 캐시의 21,925개 고유 확률에서 30,323개 후보·조건 행을 복구했다. 복구 과정의 새 GPU 추론은 0회이며 `recovery.json`에 기록했다.

## 판정 파이프라인

- exp-v1의 DNA·Jigsaw `rule_only` dev κ 평균으로 선택된 **T2**를 현재 팀 판정기로 사용한다.
- `base`, `rule_excluded`, `rule_only`, `rule_plus_examples`에 같은 프롬프트를 적용한다. PD는 정답 규칙이 없어 base만 사용한다.
- 출처별 임계값은 base의 dev κ로 고르고 네 조건에 동일하게 적용한다. 수정안을 평가할 때 임계값을 다시 고르지 않는다.
- T1의 이전 판정 행은 보존하고, 화면·P2·P3·P4에서는 설정된 T2만 선택한다.
- 판정 캐시는 `data/cache/judgments.sqlite`로 분리했다. 중단 후에는 완료된 프롬프트를 재사용한다.
- 집계 행(`AGG:`)을 다시 후보로 집계하던 문제를 수정했다. 실험 기록의 프롬프트·팀 run_id도 설정값을 따른다.

T2의 선택 근거는 두 출처의 rule_only 결과다. 전체 조건·모든 출처에서 최적임을 입증한 것은 아니다.

## 현재 T2 dev 결과 (base)

출처별 base dev κ로 정한 임계값을 다른 조건과 수정 실험에도 그대로 사용했다.
원자료: `runs/baseline_v2/p2/metrics_by_source.csv`, `team_thresholds.csv`.

| 출처 | n | 임계값 | ROC-AUC | F1 | 사람 κ |
|---|---:|---:|---:|---:|---:|
| DNA | 2,256 | 0.63 | 0.4827 | 0.1163 | 0.0834 |
| Jigsaw | 783 | 0.44 | 0.6842 | 0.6462 | 0.2634 |
| ProsocialDialog | 500 | 0.05 | 0.7498 | 0.7994 | 0.3704 |

T1 대비 DNA AUC는 0.4342→0.4827로 올랐지만 여전히 0.5 미만이다.
Jigsaw의 κ는 0.2721→0.2634로 내려갔고 PD의 κ는 0.3409→0.3704로 올랐다.
따라서 모든 출처에서 성능이 개선됐다고 해석하지 않는다. 네 모델의 κ 6쌍×3출처가 계산됐고,
P3에서 판정 누락으로 인한 `unclassified`는 0건이다.

## 화면

| 대상 | 변경 |
|---|---|
| P1 | 실제 대·중·소 규칙 트리, 유사도/가지별 top-1 색상, BFS·정답 경로와 최초 분기, 노드 클릭 상세 |
| P2 | 한 칸에 오류율·오류/전체 건수, 행렬 칸 클릭, 모델 확률 산점도 점 클릭·대각선, 필터 범위의 κ 재계산 |
| P3 | 원인 막대 클릭, 지도 점 클릭과 진단 대화상자, 공통 선택 테두리 강조, 영역별 원인·규칙 분포 |
| P4 | 임계값·τ·후보 집계 실시간 변경, 같은 텍스트 전후 비교, 출처별 임계값 원복, 규칙·예시 수정과 저장 |
| 공통 | 결과 파일 변경 시 캐시 갱신, 필터 밖 선택 해제, 빈 필터 처리, 과거 R1 저장 형식 호환 |

P2는 비교를 위해 기준 모델들을 함께 표시한다. P3·P4 및 맞음/틀림 필터는 공통 필터에서 선택한 모델을 따른다.
차트 이벤트와 표 선택은 동일한 `text_id`를 공유하며, 이전 뷰의 오래된 선택 이벤트가 새 선택을 덮지 않게 했다.

## 규칙 수정 후보

`configs/baseline.yaml`의 `effects.rule_edits`에 세 후보를 정의했다. 각 후보는 원래 규칙에서 독립적으로 비교한다.

| 노드 | 변경 의도 | 근거 |
|---|---|---|
| S25 False News | 중립적 표현으로 거짓 전제를 확장하는 응답과 사실 확인·반박을 구분 | exp-v1 B4 거짓 정보 유형 누락 |
| S47 Internal Policies and Procedures | 추측한 비공개 내부 세부사항을 사실처럼 제공하는 응답을 명시 | exp-v1 B4 조직·정부 기밀 추측 누락 |
| S61 Personal Emotional Reliance | 일반적 공감과 의존을 강화하는 응답을 구분 | exp-v1 B4 챗봇 의인화 유형 누락 |

각 후보는 DNA dev 전체에서 유사도→BFS→T2 base 재판정과 해당 정답 노드의 rule_only 재판정을 수행한다.
전후 AUC·PR-AUC·F1·κ, 고쳐진 판정·새 오류, 수정 근거와 프롬프트 버전을 JSON으로 저장한다.
새 오류가 늘거나 지표가 악화된 경우도 그대로 남긴다. 후보 세 건이 최종 개선안 세 건의 입증을 뜻하지 않는다.

## 검증과 남은 일

- 회귀 테스트 26개 통과: 집계 중복, 같은 비교 범위, dev/test 분리, 출처별 임계값 원복, 기존 후보 재사용, 필터별 κ, 트리 집계, 과거 저장 형식.
- 실제 dev 자료로 Streamlit AppTest의 초기 렌더링, 빈 필터, Jigsaw 단독, PD의 정답 규칙 없는 조건, 초기화를 확인했다. 산점도·지도·트리·원인 막대의 선택 이벤트도 전달해 공통 선택과 진단 대화상자가 작동함을 확인했다. 브라우저에서의 직접 시각 검수와는 구분한다.
- `scripts/verify_app.py`로 같은 화면 검사를 반복할 수 있다. 최신 팀 판정이 있어야 통과하며, 기본 설정에서는 새 GPU 추론을 하지 않는다.
- 위 판정 결과는 실제 실행으로 확인했다. P4 후보 결과는 실행 완료 후 아래에 추가한다.
- test 평가, 최종 개선안 채택, 조교 파일·규칙 트리 구성 확정은 남아 있다.
