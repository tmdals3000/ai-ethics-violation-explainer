# 팀원 브랜치와 차이 정리 (SeungMin ↔ Minjun)

- 비교 대상: `origin/SeungMin` (이 문서가 있는 브랜치) ↔ `origin/Minjun` `94e68e3` (DNA 만으로 만든 개인 데모). Minjun 브랜치는 읽기만 했고 고치지 않았다.
- 같은 dev 2,256건 (Minjun 은 우리 `judgments.csv` 에 있는 텍스트를 dev 로 썼다).
- **결정은 팀이 한다.** 아래 '추천안' 은 근거와 함께 적은 제안이다.

## 1. 설정 차이

| 항목 | SeungMin (우리) | Minjun | 영향 |
|---|---|---|---|
| 출처 | DNA · Jigsaw · ProsocialDialog | DNA 만 | 우리 규칙 트리에 Jigsaw 노드 3개가 더 있음 |
| 규칙 트리 노드 수 | **81** (대 6 · 중 14 · 소 61; DNA 78 + Jigsaw `J`·`J1`·`J2`) | **78** (대 5 · 중 12 · 소 61) | 효율 분모가 다름. 우리 DNA dev 298건(13.2%)의 top-1 이 Jigsaw 규칙 |
| 소분류 규칙 문장 | `"이름" (위해 유형): The chatbot shall not provide content that complies with or assists requests in this category. Scope: 설명` (평균 51.5단어) | `이름: 설명` | 두 브랜치 소분류 유사도 상관 **0.52** — P1 차이의 주원인 |
| 임베딩 입력 (DNA) | `질문\n응답` | `Q: 질문\nA: 응답` | 중분류 유사도 상관 0.88, 우리가 평균 0.050 낮음 |
| split | 고정 시드 42, train 0.2 / dev 0.4 / test 0.4, 질문 단위 (DNA), 같은 본문 단위 (Jigsaw) | 우리 판정 결과에 있는 텍스트 = dev, 나머지 = test (train 없음) | dev 는 같음. test 는 다름 (우리 test 2,256 / Minjun 3,378) |
| coords | 임베딩 PCA 2차원 | UMAP (cosine, n_neighbors 15) | P3 지도 모양이 다름. 지표에는 영향 없음 |
| Qwen3Guard Controversial 가중치 | **1.0** (strict) | **0.5** | 우리 AUC 0.794 / Minjun 0.800. 판정 확률 상관 0.988 |
| ShieldGemma 조건 | 4조건 (base 상위 5후보 max · 규칙 제외 · 규칙 문장만 · 규칙 문장 + 예시) | 규칙 문장만 | Minjun 은 P3 규칙 찾기 문제(원인 1)를 셀 수 없음 (0건) |
| ShieldGemma 프롬프트 끝 | 문장 뒤 빈 줄 2개 (`\n\n`) | 빈 줄 1개 (`\n`) | rule_only 확률 상관 0.934 (규칙 문장 차이와 섞여 있음) |
| 판정기 입력 길이 | 텍스트·맥락 각각 3,000자에서 자름 (DNA dev 3건) | 토큰 1,536에서 자름 (`truncation=True`, 오른쪽을 자르므로 프롬프트 끝의 판정 위치가 잘릴 수 있음) | Llama Guard 확률 상관 0.976, 0.5 기준 판정 14건 차이 |
| 팀 판정기 | ShieldGemma 가중치 + 팀 프롬프트 (T1, 출처별 임계값) | 없음 | P2 κ 6쌍 중 Minjun 은 3쌍만 |
| 임계값 | 기준 모델 0.5, 팀 dev 에서 출처별로 고름 | 0.5 (화면에서 바꿈) | — |
| P3 진단 | 텍스트 × 모델마다 원인 하나. 규칙 2 '라벨 확인' 은 **4개 모델** 모두 같은 답일 때, 규칙 3 '규칙 문장' 은 ShieldGemma·팀 **둘 다** rule_only 에서 틀릴 때. 결과가 빠진 모델이 있으면 `unclassified` | 모델마다 원인 하나 (같음). 규칙 2 는 **3개 모델**, 규칙 3 은 ShieldGemma rule_only **하나**로 판단 | Minjun 은 라벨 확인 138 · 규칙 문장 64 · 판정 모델 58 · 규칙 찾기 0. ShieldGemma 오류의 '판정 모델 문제' 가 구조상 0건 |
| P3 대상 판정 | 각 모델의 base 판정 | 기준 모델 default + ShieldGemma rule_only | ShieldGemma 오류 수가 다름 (우리 69 / Minjun 88) |

## 2. 같은 dev 2,256건에서 수치가 다른 이유 (추정)

| 지표 | 우리 | Minjun | 주원인 (추정, 근거) |
|---|---|---|---|
| P1 top-1 | 0.321 | 0.268 | **소분류 규칙 문장이 다름** (소분류 유사도 상관 0.52). 우리 쪽은 Jigsaw 노드로 298건을 잃는데도 더 높다 → 문장 차이의 효과가 그보다 크다 |
| P1 효율 | 0.353 (/81) | 0.399 (/78) | 우리 중분류 유사도가 평균 0.050 낮아(임베딩 입력 `Q:`/`A:` 유무) τ = 0.20 을 넘는 중분류가 적다 → 내려가는 소분류가 적다. 분모 차이(81 vs 78)는 작은 몫 |
| P1 경계 사례 | 181 | 336 | 같은 이유로 τ 근처 중분류 분포가 다름 |
| P2 Llama Guard AUC | 0.763 | 0.758 | 같은 템플릿. 자르는 방식(글자 vs 토큰) · 배치 패딩의 bf16 오차. 확률 상관 0.976 |
| P2 Qwen3Guard AUC | 0.794 | 0.800 | Controversial 가중치 1.0 vs 0.5 |
| P2 ShieldGemma rule_only AUC | 0.568 | 0.563 | 규칙 문장 + 프롬프트 끝 줄바꿈. 확률 상관 0.934 |
| P3 원인 분포 | 4개 모델 기준 | 3개 모델 기준 | 규칙 2·3 의 정의에 들어가는 모델 수가 다름 (위 표) |

확인 방법: Minjun 의 `similarity.csv`, `judgments.csv`, `rules.csv`, `results/p1_retrieval.csv` 를 우리 결과와 text_id·노드 이름으로 맞춰 비교했다.
P1 원인을 하나씩 떼어 확인하려면 (1) Minjun 규칙 문장 + 우리 입력 형식, (2) 우리 규칙 문장 + Minjun 입력 형식으로 유사도를 다시 계산하면 된다 (GPU 약 2분, 아직 안 함).

## 3. Minjun 화면에 있고 우리 화면에 없는 PDF 필수 상호작용

PDF '시스템 요구사항' 기준. 우리 화면 = `app/app.py`.

| PDF 요구 | Minjun | 우리 | 차이 |
|---|---|---|---|
| P1 '규칙 트리(대·중·소분류) 위에' 단계별 유사도 · BFS 경로 · 정답 경로를 시각화 | 트리맵 (노드 색 = 유사도, ★정답 · ✓BFS 표시) | 표 (경로가 다르면 행 강조) | **트리 모양 시각화 없음** |
| P2 '칸마다 잘못된 판정 비율과 건수' | 한 칸에 `비율 (오판/건수)` 히트맵 | 비율 표와 건수 표를 따로 | 한 칸에 둘 다 표시 안 함 |
| P2 두 모델 산점도에서 텍스트 고르기 → 모든 뷰에 연동 | 점 클릭 → 선택 | 점 클릭 안 됨 (옆의 '차이 큰 20건' 표에서 고름) | **산점도 점 클릭 선택 없음** |
| P3 지도에서 텍스트 누르기 → 진단 팝업 | 점 클릭 + 상자 · 올가미 | 상자(brush)만, 진단은 표에서 고른 텍스트 | **지도 점 클릭 선택 없음**, 올가미 없음 |
| 선택 텍스트 강조 (시각화 간 연동) | P2 산점도 · P3 지도에서 굵은 테두리 | P2 산점도 주황색, P3 지도는 강조 없음 | **P3 지도 강조 없음** |
| P1 자주 틀리는 가지 '강조' | 막대 그래프 | 색 입힌 표 | (둘 다 충족, 형식 차이) |

반대로 우리에게만 있는 것: 출처 · 분할 필터(Minjun 은 DNA dev 고정), P4 규칙 문장 편집 → 다시 판정, P4 처음 보는 규칙 4조건 AUC, P2 4조건 선택, 임시 데이터 경고.
두 화면 모두 없는 것: P2 행렬 칸 '클릭' 으로 목록 열기 (우리는 선택 상자 두 개, Minjun 은 없음), P3 원인 막대 '클릭' 강조 (우리는 선택 상자).
