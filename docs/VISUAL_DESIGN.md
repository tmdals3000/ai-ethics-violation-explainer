# Project 4 시각 분석 화면

현재 화면은 `app/app.py`의 Streamlit 앱이다. 기존 P1~P4 계산과 저장된 dev 판정을 그대로 연결하고, PDF에 제시된 세 시스템의 분석 흐름을 참고해 화면을 다시 구성했다. 디자인과 상호작용 원칙을 적용했으며, 각 논문의 학습·공격·모델 내부 분석 알고리즘을 구현한 것은 아니다.

## 실행

새로 받은 저장소에서는 `setup_dashboard.cmd`로 화면용 의존성을 설치하고 `run_dashboard.cmd`를 실행한다. 실제 dev 결과 스냅샷을 포함하므로 화면 실행에는 GPU·원본 데이터·토큰이 필요 없다. 브라우저 주소는 `http://localhost:8501`이며 `Ctrl+C`로 종료한다. [Windows·macOS·Linux 설치 명령과 전체 모델 환경 안내](LOCAL_RUN.md).

다른 환경에서는 의존성과 `configs/baseline.yaml`의 데이터 경로를 준비한 뒤 실행한다.

```bash
python -m streamlit run app/app.py
```

초기 화면은 저장된 분석 결과를 읽고 임계값 변경은 저장된 확률을 다시 집계한다. 스냅샷 실행에서는 원문 보기·새 모델 추론을 차단하며, 저장되지 않은 후보 판정이 필요한 설정에는 안내를 표시한다. 원본과 모델을 준비한 전체 환경에서는 검색 τ 변경과 규칙 편집 후 캐시에 없는 모델을 재판정할 수 있다.

AdversaFlow 공개본은 IEEE VIS 2024 발표 자료이며 PDF 과제에서는 TVCG 2025 논문으로 소개한다. Blocks의 계층은 클래스 관계를 분석한 결과지만, 이 앱의 계층은 데이터에 주어진 윤리 규칙 구조다. 두 계층의 생성 방법은 다르다.

## PDF 요구와 실제 동작

| 단계 | 화면에서 확인할 것 |
|---|---|
| 공통 | 출처·분할·규칙·모델·정오 필터, 실제 표본 수·오류 수·모델 불일치 수·검색 경계 사례 수, 탭 사이에 유지되는 선택 사례, 원문 기본 가림 |
| P1 | 규칙 계층 블록/트리, 노드별 top-1·top-3와 n, 검색/정답 경로, 최초 분기, τ 조절, top-k와 경계 사례 |
| P2 | 출처별 지표, 규칙·응답 LLM·출처별 오류율 행렬과 n, 셀 선택, 두 모델의 확률 점 선택, 모델 4개의 쌍별 κ 6개 |
| P3 | 네 오류 원인과 미분류, 진단 k 조절, 원인 선택과 지도 강조, 점 클릭 진단, 영역 선택 통계, 사례별 네 조건 확률 |
| P4 | 출처별 기준/변경 지표, 실제 건수에 비례하는 변화 흐름과 유형별 사례, 임계값·τ·집계 조절과 되돌리기, 규칙/예시 수정 후 재판정, 근거와 수정안 저장 |

공통 필터는 모든 탭에 적용한다. 원인 강조·모델 쌍·시나리오 변화 유형 등은 각 탭의 추가 탐색 조건이다. P3 지도에서 선택한 원인은 점의 강조를 바꾸며 전체 분포 좌표를 다시 계산하지 않는다.

## 데이터와 해석 범위

- 이번 UI 변경은 기존 `team_v2`와 저장된 dev 결과를 사용한다. 화면 변경을 위해 GPU 실험이나 test 평가를 다시 실행하지 않았다.
- split·유사도·좌표·판정의 조교 제공 파일이 없으면 기존 파이프라인의 임시 결과를 사용하며 데이터 상태 안내에서 표시한다. 현재 지도는 PCA 2D로, 원 논문의 t-SNE를 재현한 것이 아니다.
- 지도상의 가까움은 텍스트 표현의 유사성이다. 오류 원인은 기존 P3의 조건별 판정 규칙으로 계산한다.
- 흐름은 같은 텍스트 집합의 **이진 판정 정오 변화**다. 공격 경로·원인 간 인과관계·학습 개선을 나타내지 않는다.
- 규칙 개선 후보와 dev 성능은 검토 자료다. UI 완성 자체가 최종 test 성능 개선을 증명하지 않는다.

## 구현 위치

- `app/app.py`: 데이터 연결과 네 분석 탭, 공통 선택·클릭 이벤트, 기존 재판정 연결
- `app/ui.py`, `app/styles.css`, `.streamlit/config.toml`: 화면 구성·색상·요약 카드
- `src/visuals.py`: 계층 블록 범위, 사례별 정오 변화와 건수 비례 흐름
- `tests/test_visuals.py`: 계층 포함 관계와 변화 건수 보존 검증
- `scripts/verify_app.py`: 저장된 실제 dev 결과로 초기 화면·필터·되돌리기·차트 선택을 확인하는 AppTest

## 검증 기록 (2026-11-12)

- `python -m pytest -q`: **30개 통과**. 기존 회귀 검증에 계층 블록의 부모/자식 범위, 확대 시 좌표 유지, 동일 사례 집합, 정오 변화 분류와 흐름 건수 보존 검증 4개를 추가했다.
- `python scripts/verify_app.py`: **14개 확인 지점 통과**. 초기 화면, 빈 필터, Jigsaw와 PD, 조건 변경, 임계값 변경, 변화 흐름 선택, 원복, 팀 모델, 산점도/지도/계층/원인 선택, 가지 확대를 실제 저장 결과로 확인했다.
- 로컬 HTTP 응답 200, Chrome에서 네 탭의 차트 7개가 로드되고 각 탭에 Streamlit 앱 예외가 없음을 확인했다. 화면은 [`screenshots/`](screenshots/)에 저장했다.
- 브라우저에서 임계값 직접 지정을 켜고 키보드로 1.00으로 바꿔 재계산했다. 최종 dev 3,539건은 맞음 유지 2,416 / 고쳐짐 300 / 새 오류 546 / 오류 유지 277이었다. 이 값은 UI 동작 확인용으로 고른 극단적 설정이며 개선안이 아니다. AUC는 확률 순위 지표이므로 임계값만 바꾸면 그대로이고 F1·κ와 이진 판정은 바뀐다.
- 이 PC의 샌드박스에서는 pytest 캐시 생성과 AppTest 종료 시 임시 폴더 정리에 권한 경고가 발생했다. 테스트 검증과 앱 예외 검사는 통과했고 종료 코드는 0이었다.
